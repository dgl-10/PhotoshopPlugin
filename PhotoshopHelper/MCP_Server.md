# MCP-сервер

Локальный MCP для AI-агентов на той же машине. Вешается на уже существующий
Express и тот же исполнитель, что Local Generation API. Это не второй пайплайн
генерации, не публичный сервис и не удалённый хост.

Эндпоинт: `http://127.0.0.1:18345/mcp`

Helper уже должен быть запущен (трей или `npm start`). Отдельный процесс,
отдельный порт и `stdio` не нужны. Пользователю установленного приложения
системный Node.js не нужен. Слушать только `127.0.0.1`, не публичный деплой.
В клиентах писать `127.0.0.1`, не `localhost` (на части машин это IPv6 и отказ).

## Суть

MCP — тонкий адаптер над Local API. Проверки путей, роли картинок, вызов
провайдера, запись файлов, temp-каталог и учёт использования уже есть.
Не дублировать это в MCP и не ходить в Local API по HTTP с поллингом.

Local API остаётся `202` + poll. `generate_image` в MCP дожидается конца
исполнителя: агентам проще один синхронный результат, чем цикл опроса.

Реестр задач WebHelper / Photoshop не трогать. Результаты — абсолютные пути
в общей temp-папке, не слой Photoshop.

## Транспорт

Только текущий Streamable HTTP (`GET` / `POST` / `DELETE` на `/mcp`), SDK
`StreamableHTTPServerTransport`. Без устаревшего HTTP+SSE и без `stdio`.

Сессии — `Map` по `mcp-session-id`. Один глобальный transport нельзя: два
локальных клиента не должны сбивать друг друга.

Тело запроса уже разобрано глобальным `express.json()` — отдать его в SDK,
не ставить второй raw-body парсер.

Долгие `generate_image` могут ждать до 600 секунд. Поднять
`httpServer.requestTimeout`, иначе соединение оборвётся и это будет похоже
на баг клиента.

На выходе из трея закрыть транспорты в уже существующем shutdown.

CORS не расширять до «пускай всех». Десктопные клиенты его игнорируют;
если что-то нужно для браузерных локальных клиентов — аккуратно, в духе
уже принятой политики приложения.

## Аутентификация

Тот же секрет, что у Local API (платный вызов провайдера), не токен плагина.
Токен обязателен. Нельзя оставлять `/mcp` открытым на loopback «потому что
локально». Если клиент не умеет слать токен — будет 401; это ожидаемо.

## Что видит агент

Короткий handshake в `instructions`, не весь гайд:

1. Это локальный tool-сервер генерации картинок.
2. Сначала `list_providers`, потом `get_providers_details` только для
   выбранных id, потом `generate_image`.
3. Входы и выходы — абсолютные пути. Файлы пишутся в общий temp, не в Photoshop.
4. Если застрял — можно прочитать `MCP_GUIDE.md` по абсолютному пути
   из `getConfigPaths().resourcesPath`. Не хардкодить `file://` разработчика.

Гайд в результаты инструментов не класть. Описания инструментов сами несут
жизненный цикл, чтобы модель не дергала details по всем провайдерам каждый ход.

## Инструменты

Три штуки. Без MCP Resources и без виртуальных URI.

**`list_providers`** — лёгкий список тех, у кого на месте ключи и есть
валидные `generation_modes` (`t2i` / `i2i`). Тот же скан ключей, что у
`GET /api/webhelper/providers`, не вторая реализация. Без схем, remarks и
UI-лейблов. Опциональный фильтр по режиму.

**`get_providers_details`** — схема уже выбранных id. Не для всех подряд,
wildcard `*` не принимать. Неизвестные / без ключа id идут в `notFound` и
не валят весь вызов. Отдать модели то, что нужно звать `generate()`:
имена параметров, типы, default, значения dropdown (не UI-алиасы), слайдеры,
режимы, лимиты референсов и aspect ratio в той форме, в какой они заданы
в конфиге (в том числе `{ default, depends_on, values }`). WebHelper-хром
срезать. Внутренности маски (`type`, `field_name`) не светить.

**`generate_image`** — дождаться исполнителя. `providerId` из списка;
провайдерные ключи в `params` под именами из details; верхний `prompt`
перебивает `params.prompt`. Дальше те же правила Local API: абсолютные
существующие файлы, t2i без картинок требует `aspect_ratio`, первый
референс может стать source, маска без source — ошибка. Таймаут —
только MCP, в `generate()` не уходит.

Битый ввод (относительный путь, нет ratio у t2i, `*`, плохие типы) —
ошибка инструмента, генерации нет. Сбой провайдера/режима/маски внутри
исполнителя — успешный вызов со `status: "failed"`, не протокольный throw:
иначе агент просто перезапустит генерацию.

По таймауту тоже `failed` с явной ошибкой про время. Поздних файлов
отдельным инструментом не достаём.

## Гайд и упаковка

`MCP_GUIDE.md` — короткий файл для модели (~100 строк): жизненный цикл,
как типы UI ложатся в `params`, модальности, три примера. В dev лежит
рядом; в сборке — через `extraResources`, как `Local_Generation_API.md`
(обычные `*.md` в пакет не попадают).

`@modelcontextprotocol/sdk` — обычная зависимость приложения, как Express.
Приложение CommonJS: предпочесть CJS-импорт, ESM-interop не расползать
на весь проект.

Эта спецификация в инсталлятор не входит.

## Куда класть код

MCP держать вне `main.js`, кроме монтирования и shutdown. Существующие
файлы не раздувать — новые модули нормальны.

Нормализацию и execute вынести из `localGenerationApi.js` и звать напрямую.
Скан ключей провайдеров — один на WebHelper и MCP. Проверку токена не
копировать: взять уже существующую аутентификацию приложения.

## Экспорт только ради тестов

Если функция в `module.exports` нужна снаружи только тестам — пометить это
в зоне экспорта комментарием. Если её зовёт рантайм (main, MCP, Local API),
это не «только для тестов», даже когда тесты тоже импортируют.

Не экспортировать «на всякий случай».

## Не делать

Устаревший SSE, `stdio`, Resources / `pshelper://`, укладку в Photoshop,
четвёртый инструмент статуса/отмены, новый планировщик очереди,
удалённый/туннельный режим как штатный, перевод приложения на ESM.
