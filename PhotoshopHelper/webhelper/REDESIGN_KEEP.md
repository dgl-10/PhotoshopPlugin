# WebHelper redesign — что сохранить

Короткий рабочий список. **Вычёркивай / удаляй** что не важно, **дописывай** своё.

Это не описание текущего UI и не запрет менять схему работы. Редизайн полный:
вкладки, что происходит после Generate, раскладка, фреймворк — всё можно менять.
Здесь только фичи и принципы, которые жалко потерять.

Подробный снимок «как сейчас устроено» (на всякий случай):
[`REDESIGN_PRESERVATION.md`](REDESIGN_PRESERVATION.md).

---

## Принципы

- Клиентский редизайн. Сервер не трогаем, пока отдельно не решим, что без этого нельзя.
- Форма живёт от `providers.json`: модели, параметры, маска, лимиты рефов, T2I/I2I. Не хардкодить конкретные модели в UI.
- Есть **local** и **не-local** (ngrok / туннель / телефон). Это реальный рабочий режим, не баг. Нигде нормально не задокументирован, но им пользуются. Не схлопывать в «только localhost».

## Задачи

- Задача из Photoshop (картинка + маска), подхватывается сама.
- Задача без картинки (text-to-image).
- Задача из внешней картинки: файл, drag-and-drop на страницу, paste.
- Новая задача из готового результата (цепочка).
- Несколько задач сразу, переключение между ними.

## Картинки внутри задачи

- Превью source.
- Маска: видно, что красится; можно смотреть картинку / маску / оверлей; маску можно не слать, если провайдер позволяет.
- Референсы у задачи.
- **Global Stage** — общая куча картинок на все задачи.
- Drag-and-drop: с диска, между Global Stage и рефами задачи, и обратно.
- Сортировка рефов перетаскиванием.
- Paste картинки в рефы.
- Touch: то же самое на телефоне (через туннель).
- Local: Alt+Drag из Global Stage наружу (в проводник / браузер / Photoshop).

## Генерация

- Выбор провайдера из тех, что сервер реально отдал (есть ключи).
- Промпт. Negative prompt, если провайдер умеет.
- Динамические параметры провайдера (dropdown / слайдер / чекбокс / число).
- Память aliased-параметров при смене провайдера (resolution и т.п. не сбрасываются в ноль).
- Число картинок. Aspect ratio: для T2I обязателен, для I2I можно «как вход».
- Несколько результатов у одной задачи, старые не пропадают.
- Повторить генерацию с теми же настройками.
- Скачать результат.
- Local: копировать результат в буфер (вставить в Photoshop).
- Замечания провайдера (`remarks`) показать, если они есть.

## Local vs не-local

- Local: поллинг задач из Photoshop; полный файл результата; copy в буфер; Alt+Drag наружу.
- Не-local: своя сессия, чужие/Photoshop-задачи не приезжают; без copy в системный буфер; картинки можно отдавать превью (полный файл — скачать); без Alt+Drag в OS.
- Same-origin + HTTP Basic, если задан пароль на туннель. Отдельный логин-экран в SPA не обязателен.

## Сюда дописать

- Показ сгенерированных картинок отличается между local и не-local версиями: в локальной версии всегда выводится полная картинка, в не-локальной — оптимизированная (превью/сжатая).
- Alt+Drag (перетаскивание наружу в проводник / браузер / Photoshop) работает только в локальной версии; на не-локальной версии он отключён.
- **Строгое сохранение различий Local vs Не-Local**: внимательно следить за поведением и полностью сохранить всю текущую разницу в логике между локальной и не-локальной версиями.


## Новые фичи

- Drag-and-drop основной (source) картинки в Global Stage (как минимум) и возможность Alt+Drag наружу в локальной версии.
- **Умный комбобокс моделей / провайдеров**:
  - Быстрая и отзывчивая работа UI.
  - Введение **тегов**: возможность сортировки (и фильтрации) моделей по тегам.
  - **Фавориты (Избранное)**: добавление моделей в фавориты, режим отображения только избранных в сочетании с сортировкой.
  - **Хранение в Cookies** (на текущем этапе):
    - Список избранных моделей (фаворитов).
    - Последний выбранный state этого комбобокса.
- **Отображение результата**: сгенерированная картинка должна полностью помещаться на экране и быть видна целиком без необходимости скроллинга страницы.


## Как делать

- **Новый WebHelper рядом (side-by-side)**: редизайн строится как отдельная новая HTML-страница (совершенно новый интерфейс), текущий WebHelper не трогаем и сохраняем рабочим, чтобы в любой момент можно было вернуться, сверить поведение или посмотреть, как было реализовано.
- **Выбор стека и фреймворков (JS / CSS)**:
  - Свобода в выборе технологий (JS-библиотеки/фреймворки, CSS) — ограничений на использование библиотек или обязательный Spectre.css нет.
  - Главные условия:
    - Должно без проблем отдаваться и обслуживаться существующим локальным Express-сервером `PhotoshopHelper` (без необходимости менять/переписывать бэкенд).
    - Баланс и легковесность: код выполняется на машине конечного пользователя (и на смартфонах через туннель), поэтому решение должно быть быстрым, легковесным и без избыточного оверхеда.
- **Стилистика и палитра**: ориентироваться на лендинг в GitHub Pages ([`docs/index.html`](../../docs/index.html)), взяв оттуда цветовую гамму, фон и общий визуальный язык.
- **Компактность и минимизация «мёртвых зон»**:
  - Лендинг слишком «воздушный» (крупные блоки, большие паддинги и скругления) — интерфейс WebHelper должен быть **намного более компактным и плотным**.
  - Даже текущий WebHelper недостаточно компактен: в нём слишком много мёртвых зон и потерянного места (особенно в хедере).
  - Из-за мёртвых зон сгенерированная картинка получает меньше доступного пространства на экране и отображается меньше, чем могла бы.
  - В новом интерфейсе мёртвые зоны должны быть сведены к минимуму, чтобы дать максимум экранного пространства картинке-результату.


## Компоновка и видение UI

### Desktop (двухколоночный компактный лэйаут)
- **Header / Top Bar (сверху в одну компактную строку)**:
  - Global Stage (общая полка картинок).
  - Статус подключения (Connection status).
  - Основные действия (кнопка `New Task` и др.).
  - Комбобокс задач (переключение между текущими тасками).
- **Левая колонка (Source & Настройки)** — относительно узкая панель (скроллится при необходимости):
  - Превью исходной картинки (source) — компактный размер.
  - Управление маской (показ/скрытие, оверлей).
  - Референсы задачи (ref zone).
  - Поле промпта (и negative prompt при наличии).
  - Динамические параметры провайдера/модели.
  - Фиксированные параметры (aspect ratio, num outputs) + кнопка **Generate**.
- **Правая колонка (Результаты)** — широкая область для картинок:
  - **Карусель результатов**: отображение сгенерированных картинок крупно (помещается 2 или 1.5 карточки по ширине с плавной горизонтальной прокруткой).
  - **Лента миниатюр (Thumbnails)**: снизу превью всех вариантов/моделей для быстрого переключения.
  - **Карточка результата**: метаданные (модель, параметры), заметная и удобная кнопка **Download**, кнопки повтора и создания новой задачи из результата.

### Mobile (адаптация под смартфон через туннель)
- Свобода компоновки под мобильный экран отдана на усмотрение разработчика.
- Обязательна полная поддержка тача: свайпы карусели, touch drag-and-drop рефов, быстрая загрузка и адаптивный компактный вид.
